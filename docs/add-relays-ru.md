# Как добавить релеи Telegram через бота

Релей нужен боту на сервере, с которого `api.telegram.org` недоступен: сейчас это почти все
российские хостинги. Бот отправляет запросы релею, а тот пересылает их в Telegram.

Порядок такой: разверните релей, проверьте его и отправьте боту `/relays add <адрес>`.

## Что работает сейчас

Проверено 2026-11-03 с 8 российских хостингов через [Globalping](https://globalping.io).

| Адрес | Результат |
|---|---|
| `api.telegram.org` | Отвечает 1 из 8, остальные не могут открыть соединение |
| `cod2admin-telegram-relay.cod2admin.workers.dev` (общий, Cloudflare) | **Работает**, 8 из 8 |
| `cod2admin-telegram-relay.cod2admin.deno.net` (общий, Deno) | **Отключён**: `503 USAGE_EXCEEDED`, исчерпан бесплатный лимит |

Сейчас у всех ботов с настройками по умолчанию остался один рабочий общий релей. Поэтому стоит
добавить хотя бы один свой.

## Сколько релеев нужно

Двух-трёх на **разных платформах** достаточно. Важнее разнообразие, чем количество:

- Несколько релеев на одном аккаунте делят один лимит и закончатся одновременно.
- Релеи на одной платформе обычно блокируются вместе, потому что у них общий домен.
- Не заводите дополнительные аккаунты, чтобы обойти бесплатные лимиты: это может нарушать правила
  платформы, и она может закрыть аккаунт вместе с релеем.

Один бот делает примерно 2 900 запросов в сутки (один длинный запрос каждые 30 секунд) плюс
запросы на сообщения и команды.

## Шаг 1. Выберите платформу

| Платформа | Доступность из РФ | Бесплатно | Подходит? |
|---|---|---|---|
| **Cloudflare Workers** | 8 из 8 | 100 000 запросов в сутки, сброс в полночь UTC | **Да.** Но российские провайдеры режут соединения после 16 КБ; бот это учитывает |
| **Val Town** | 8 из 8 | 100 000 запусков в сутки | **Да, самый простой вариант:** всё делается в браузере |
| **Netlify** | 7 из 8 | Кредиты: по сторонним данным, 300 в месяц | **Да, как запасной.** Расход кредитов на релей не проверен, следите за ним в панели |
| **Deno Deploy** | 8 из 8 | По сторонним данным, 1 млн запросов в месяц | **Да.** Лимит ниже, чем у Cloudflare: примерно 33 000 запросов в сутки |

Эти платформы не подходят или требуют отдельной проверки:

| Платформа | Почему |
|---|---|
| Vercel, Render | Отвечают только 3–4 из 8 |
| Koyeb | Доступен (8 из 8), но может потребовать банковскую карту. Один бесплатный экземпляр на организацию |
| Hugging Face Spaces | Доступен (8 из 8), но в документации Docker Spaces указаны как платные |
| Fastly Compute | Доступен (8 из 8), но нужен другой код релея. Если на аккаунте есть карта, сверх лимита начнутся списания |
| bunny.net | Доступен (8 из 8), но бесплатен только пробный период: 14 дней |
| Fly.io, Supabase | Доступность не измерена: у этих проверок не было настоящего адреса на платформе |

Лимиты меняются, поэтому перед развёртыванием сверьтесь с тарифами платформы.

## Шаг 2. Разверните релей

Рецепты для Val Town и Netlify составлены по документации, но ещё не проверены настоящим
развёртыванием. Поэтому обязательно выполните шаг 3.

Запускайте команды **вне этого репозитория**.

### Val Town

1. Зарегистрируйтесь на [val.town](https://www.val.town) и создайте новый **приватный** val с
   HTTP-триггером. Публичный делать нельзя.
2. Вставьте в него содержимое файла
   [`packages/telegram-relay/src/lib/relay.ts`](../packages/telegram-relay/src/lib/relay.ts).
3. Добавьте в конец файла строку:
   ```ts
   export default (request: Request) => handleRelayRequest(request);
   ```
4. Скопируйте адрес вида `https://<имя>.val.run` со страницы val.

Val Town хранит логи 3 дня. Мы не проверяли, попадают ли туда пути запросов, а в пути есть токен
бота. После первого запроса откройте логи val. Если токен там виден, никому не показывайте логи.

### Netlify

1. Создайте папку такого вида:
   ```text
   relay-netlify/
     public/index.html                  любой файл, например пустая страница
     src/relay.ts                       копия packages/telegram-relay/src/lib/relay.ts
     netlify/edge-functions/relay.ts    код ниже
   ```
2. Запишите в `netlify/edge-functions/relay.ts`:
   ```ts
   import { handleRelayRequest } from '../../src/relay.ts';

   export default (request: Request) => handleRelayRequest(request);
   export const config = { path: '/*' };
   ```
3. Опубликуйте релей, указав своё имя сайта. Команда выведет адрес вида `https://<имя>.netlify.app`.
   ```sh
   pnpm dlx netlify-cli login
   pnpm dlx netlify-cli deploy --prod --dir public --site-name <имя>
   ```

### Cloudflare и Deno

Инструкции для своего аккаунта есть в
[`packages/telegram-relay/README.md`](../packages/telegram-relay/README.md#deploying-your-own).
Команду для Cloudflare, в отличие от остальных, запускайте из папки `packages/telegram-relay`.

## Шаг 3. Проверьте релей

**Сам релей.** Правильный ответ — `{"ok":true,"telegramStatus":302}`:

```sh
curl https://<адрес-релея>/health
```

**Доступность из России.** Подставьте адрес релея без `https://` и получите `id` проверки:

```sh
curl -s https://api.globalping.io/v1/measurements \
  -H 'content-type: application/json' \
  -d '{"type":"http","target":"<адрес-релея>","locations":[{"country":"RU"}],"limit":8,"measurementOptions":{"protocol":"HTTPS","request":{"method":"GET","path":"/health"}}}'
```

Через несколько секунд запросите результат. У каждой сети должен быть код `200`:

```sh
curl -s https://api.globalping.io/v1/measurements/<id> \
  | jq -r '.results[] | "\(.probe.network): \(.result.statusCode)"'
```

## Шаг 4. Добавьте релей в бота

Отправьте боту от имени владельца:

```text
/relays add https://<адрес-релея>
/relays test
```

Перед сохранением бот проверит, что через этот релей доступен Telegram. Изменения применяются
сразу, перезапуск не нужен. Если ботов несколько, добавьте релей в каждого: список у каждого свой.

| Команда | Что делает |
|---|---|
| `/relays` | Показывает маршруты и текущий маршрут |
| `/relays test` | Проверяет все маршруты |
| `/relays add <https://адрес>` | Добавляет релей в конец списка |
| `/relays remove <номер или адрес>` | Удаляет релей |
| `/relays direct on` или `off` | Включает или отключает прямой доступ к `api.telegram.org` |
| `/relays reset` | Возвращает настройки по умолчанию и удаляет добавленные релеи |

Что важно знать:

- **Порядок.** Бот пробует маршруты сверху вниз. Отдельной команды для смены порядка нет: чтобы
  поднять релей выше, удалите стоящие перед ним и добавьте их снова.
- **Обновления списка.** После первого изменения бот работает только со своим сохранённым списком.
  Новые общие релеи из обновлений бота в него не попадут, пока вы не выполните `/relays reset`.
- **Боты вне России.** Если прямой доступ работает, релеи им не нужны. Не расходуйте на них лимиты.
- **Безопасность.** Токен бота проходит через релей, поэтому добавляйте только релеи, которые
  развернули вы сами или кто-то, кому вы доверяете.

## Если что-то не работает

| Что видно | Что это значит | Что делать |
|---|---|---|
| `Couldn't reach Telegram through ...` | Релей не прошёл проверку, список не изменился | Проверьте `/health` (шаг 3) |
| `no answer within 10s` | Релей не отвечает с сервера бота | Проверьте его доступность из России и выберите другую платформу, если он заблокирован |
| `Telegram rejected the bot token` | Telegram отклонил токен | Проблема в токене бота, а не в релее |
| ❌ с ошибкой разбора JSON или `HTTP 5xx` в `/relays test` | Платформа отвечает своей страницей ошибки вместо ответа Telegram: релей отключён или исчерпал лимит | Откройте панель платформы и проверьте лимиты |
| `503 USAGE_EXCEEDED` в `/health` | Лимит Deno исчерпан | Проверьте расход в [console.deno.com](https://console.deno.com). Точный срок сброса в документации не указан |
| `Error 1027` в `/health` | Суточный лимит Cloudflare исчерпан | Дождитесь полуночи по UTC |
| `... is already in the list.` | Этот адрес уже есть в списке | Ничего делать не нужно |

Подробнее о том, почему всё устроено именно так:
[`docs/PLAN-russia-access-ru.md`](PLAN-russia-access-ru.md).
