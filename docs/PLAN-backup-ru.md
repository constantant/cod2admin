# Экспорт / импорт бэкапа — кратко

Статус: **план от 2026-11-25, ничего не сделано.** Полный текст: `docs/PLAN-backup.md`.

## Зачем

Сейчас баны, админы, серверы (с RCON-паролями), аудит, заметки, известные игроки и свои функции
лежат только в Postgres на том же хосте, что и бот. Нужен один файл, из которого можно всё
восстановить после потери хоста, поломки базы или переезда.

## Решения

- **Экспорт на уровне приложения**, а не только `pg_dump`: работает с любой базой (локальная,
  внешняя, dev), не требует `pg_dump`, файл можно проверить до применения и он переживает смену схемы.
- **Нужна командная строка** `cod2admin-backup`: на чистой установке нет владельца, и в Mini App
  войти некому. В Mini App тоже будут экспорт и импорт, но для уже работающего бота.
- **Секреты перешифровываются паролем-фразой.** В файле нет ничего, что открывается только
  ключом `SECRETS_ENCRYPTION_KEY` старого хоста, поэтому можно переехать на новый хост с новым ключом.
- **Импорт заменяет данные**, а не сливает (слияние банов позже). Всё в одной транзакции.
- **Только владелец:** новое право `backup.manage`, не передаётся другим.

## Что в файле

`core` (админы, права, серверы, настройки), `bans`, `history` (аудит, репорты, заметки, снимки,
известные игроки), `functions`. Данные `watch` по умолчанию выключены. Сессии MCP не
сохраняются. Тест следит, чтобы новая таблица не выпала из бэкапа незаметно.

Формат: gzip + NDJSON потоком, у каждой таблицы свой список колонок, контрольная сумма в конце.

## Импорт

Сначала проверка без записи (версии, счётчики, предупреждения), потом автоматический снимок
текущей базы, потом замена в одной транзакции с выравниванием sequence. После импорта через Mini
App шлюз перезапускается так же, как при `/update`.

## Расписание: бэкап в Telegram (добавлено 2026-11-25)

- Бот по расписанию присылает зашифрованный файл документом в личку владельцу (не в группу).
  Расписание: `/backup schedule daily 04:00`, `/backup off`, `/backup now`, то же на странице Mini App.
- Раз файл лежит в облаке Telegram, **шифруется весь файл** (AES-256-GCM по частям, ключ из
  парольной фразы), а не только секреты. Без фразы файл бесполезен, потеряв её, восстановить
  нельзя, и страница об этом предупреждает.
- Фраза не вводится в чат: берётся из `BACKUP_PASSPHRASE` или задаётся в Mini App и хранится
  зашифрованной в `settings`. Без неё расписание не включится.
- Копия всегда сначала пишется в `backups/` (последние 7), сбой Telegram ничего не теряет.
- Отправка идёт через существующие маршруты (реле Deno/Cloudflare), значит работает и на хостах в РФ.
  Лимит Bot API 50 МБ: если файл больше, сначала убираем `history`, потом режем на части по 45 МБ,
  а если и это не нужно, шлём только сообщение «копия готова на хосте».
- Сбой: два повтора, затем сообщение владельцу «backup failed: причина» (без секретов).
  Пропущенный запуск догоняется при старте.

## Этапы

B1 библиотека и тесты на реальном Postgres. B2 CLI и шаг восстановления в установщике. B3 страница
в Mini App. B4 бэкапы по расписанию в Telegram с ротацией. B5 документация, рецепт `pg_dump`, слияние банов.

## Вопросы к владельцу

- Оставлять ли `audit_log` в экспорте по умолчанию (большой, с IP)? Предлагаю да, с галочкой.
- Парольная фраза для расписания лежит на хосте (env или зашифрованно в `settings`). Подходит?
- Хватит ли «раз в день в заданное время» или нужно ещё «каждые N часов»?
- Файл больше 50 МБ: резать на части или достаточно убрать `history` и уведомить?
- Нужно ли вообще восстанавливать данные `watch`?
